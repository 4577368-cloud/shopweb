# 订单中心 · 升级步骤规划（基于审计整改清单）

> 本文件是 `ORDER_CENTER_VISUAL_AUDIT_PRD.md` 的**执行化延伸**：把审计出的 P0/P1/P2 与后端缺口，编排成有依赖顺序、可落地的升级步骤。
> 状态：**规划阶段，暂不开发**。每一批都沿用「逐文件手术式 + git diff 自检 + 绝不 checkout 用户文件」铁律。

---

## 0. 编排原则

1. **前端能独立做的先做，后端卡死的并行挂起** —— 避免做出"点了报错/静默无反应"的半截假控件（守「不做 AI 感无意义东西」底线）。
2. **先诚实化、去死交互（A 批）→ 再接真实数据（C 批）→ 最后增强（D/E 批）**。
3. 每步完成口径：`npx tsc --noEmit` 0 错；`git diff` 确认只动目标文件。

---

## 1. 升级总览（5 批）

| 批次 | 步骤 | 类型 | 前置 |
|------|------|------|------|
| **A 批（前端 P0）** | U1 导航整合+去假涨跌 / U2 头部清理 / U3 详情抽屉 / U4 诚实化 | 纯前端 | 无 |
| **B 轨（后端，并行）** | B1 line_items / B2 下单接口 / B3 批量反查 / B4 物流双轨 | 后端 | 与 A 并行 |
| **C 批（前端接真实）** | U5 商品明细+采购动作 / U6 物流双轨+国家+状态动作 | 需 B1/B2/B4 | A 完成 + B 就绪 |
| **D 批（P1 增强）** | U7 排序/批量/分页/刷新/图/空态/色板/Copilot 去重 | 纯前端 | A 后任意 |
| **E 批（P2 可选）** | U8 密度/视图/快捷键/toast/响应式 | 纯前端 | 任意 |

## 2. 升级步骤详解

### U1 — 导航整合 + 去假涨跌（P0-1 / P0-2）

- **目标**：全站只有一种状态导航；所有数字真实派生。
- **改动**：
  - `src/components/order/order-status-cards.tsx`：去掉 `onClick` 切 Tab，降为只读概览；当前状态用 `ring` 高亮；计数来自 `byStatus` 真实派生。
  - `order-center/page.tsx:33-41` 删除 `DELTAS` 硬编码；状态卡子指标改为「今日新增 / 待处理 / 超时」（从 `orders` 计算，纯前端可得）。
  - Tab 药丸（page.tsx:291-313）保持**唯一导航主体**，8 状态 + 全部，带计数徽标。
- **验收**：只有一种状态导航控件；页面无硬编码数字。

### U2 — 头部操作区清理（P0-3 部分）

- **目标**：无死按钮；导出真实可用。
- **改动**：
  - 移除 page.tsx:230-236「创建订单」按钮（概念错：订单来自 Shopify 拉取，不应手动建）。
  - page.tsx:223-229「导出」接真实 CSV handler（复用 `order-agent-panel` 的导出逻辑，单一实现；列与当前视图一致）。
  - 加「刷新」按钮（触发重新 `fetchOrders`；更新时间文本预留）。
  - **「重新下单」按钮不在本步放出**（等 B2 下单接口就位）。
- **验收**：头部零死按钮；点导出下载当前筛选结果 CSV。

### U3 — 详情抽屉（P0-4 / P0-5，最大价值）

- **目标**：点行看全字段；去掉死「更多」。
- **改动**：
  - 新建 `src/components/order/order-detail-drawer.tsx`，右侧滑出。
  - 渲染设计稿 §2.3 字段矩阵：店铺订单号 / Tangbuy 单号(占位) / 创建时间 / 状态 / 支付状态；按状态区块（待补款/待支付/备货中/待发货·待送达/已送达/已取消）；成本汇总（商品/物流/合计，先用 mock 字段）。
  - 内嵌物流双轨迷你进度条（新建 `logistics-tracks-mini.tsx`），先用 mock 轨迹跑通交互，B4 就绪再接真实。
  - `order-table.tsx:182-188`「更多」`ChevronDown` 并入抽屉入口（改为「查看」）或移除。
- **验收**：点任意行开抽屉，可见 §2.3 全字段（mock 即可）；无死「更多」。

### U4 — 数据可用性诚实化（P0-6 / P0-7 / P0-8 占位部分）

- **目标**：不存在的数据不假装可用。
- **改动**：
  - `order-filter-bar.tsx`：国家 / 物流停滞筛选在无字段时 `disabled` + tooltip「待数据接入」。
  - page.tsx:244-258 loading 改骨架屏（新建 `order-skeleton.tsx`）。
  - 回退 mock 时顶部横幅「接口异常，已降级为示例数据」（page.tsx 顶部条件渲染）。
  - 商品列（`order-table.tsx`）：`lineItems` 为空时显示「待同步商品明细」+ 用已有 `outerOrderId` 拼**正确** Shopify Admin 链接（真可用跳转，不依赖后端补数据）。
- **验收**：无假可用控件；回退有告警横幅；商品列不留白假象。

> ✅ **A 批交付点**：订单中心 v1。

### 后端 B 轨（与 A 并行，不阻塞前端）

| 接口 | 解锁前端 | 契约要点（Shopify 订单对象字段现成可得，成本均低） |
|------|----------|----------|
| **B1** `order/header/list` 补 `line_items` | P0-8 真实明细 / 按商品搜索 / 采购反查基础 | 每单加 `line_items[]:{title, sku, quantity, image, variantId}`（推荐方案，列表一次到位）或新增 `order/detail` |
| **B2** 按 Shopify 订单向货源下单 | 「重新下单」按钮 / 采购链路 | 入参：订单行→已关联 offer；出参：`supplierOrderNo` |
| **B3** 按一批 SKU 批量反查 offer | 多行订单反查（§5 #1） | 入参 `sku[]`；出参 `sku→offerId/offerSkuId` |
| **B4** 物流双轨（五楼+承运商）/ 订单头补 `country_code` | Phase 5 真实物流 / 国家筛选 / 状态动作 | 轨迹节点 + 国家码 |

> 依赖：B1 是 B2/B3 的输入前提（先有 `line_items` 才能反查/下单）。`order/detail` 非必需——B1 投影补字段更省。

### U5 — 接入真实商品明细 + 放出采购动作（P0-8 根治 + P0-3 完整）

- **前置**：B1 + B2（+B3 多行反查）。
- **改动**：
  - `src/lib/order/api.ts` 的 `mapShopOrderHeader` 填 `lineItems`（来自 B1）。
  - `order-table.tsx` 商品列渲染真实 title/sku/qty/图；搜索按标题/SKU 对真实单生效。
  - 详情抽屉商品区渲染真实 `lineItems`。
  - 待下单行 / 抽屉露出「重新下单」按钮：点按 → 用 `line_items` 的 sku 反查 offer（B3 或本地 `currentBinding`）→ 调 B2 下单 → 状态流转 待补款 / 待支付。
- **验收**：待下单见真实商品；点「重新下单」生成采购单（依赖后端）。

### U6 — 物流双轨 + 国家 + 状态上下文动作（Phase 5）

- **前置**：B4。
- **改动**：
  - `logistics-tracks-mini.tsx` 接 B4 真实轨迹（国内段 + 国际段双进度条，异常 warning/danger 色）。
  - 国家筛选启用（来自 B4 `country_code`）。
  - 按状态动作：待发货「标记已发货」/ 待送达「填五楼单号」等（后端就绪后启用；就绪前灰态标注，不可误点）。
- **验收**：物流双轨真实可视化；国家可筛；状态动作可用。

## 3. 依赖关系

```
A 批 (U1→U2→U3→U4)  ──无依赖，立即开工──▶ 订单中心 v1（诚实）
        │
        ├──▶ B 轨 (B1→B2/B3, B4)        ──后端并行──┐
        │                                            │
        └──▶ D 批 (U7)  ──A 后任意穿插──┐            │
                                         │            │
                              C 批 (U5←B1+B2+B3) ◀────┘
                              C 批 (U6←B4)      ◀────┘
                                         │
                              E 批 (U8)  ──随意──┘
```

- A 批无任何依赖，可立即开工。
- B 轨与 A 并行；**B1 必须先于 B2/B3**（先有 `line_items` 才能反查/下单）。
- C 批严格依赖 B 轨。
- D 批纯前端，A 批后即可穿插。
- E 批随意。

---

## 4. 推荐开工顺序（若要动手）

**A 批 U1→U2→U3→U4** 先交付诚实 v1 → 同时推 **B 轨** → B 就绪后 **C 批 U5/U6** → 并行 **D 批 U7**。E 批按需。

> 这样每一批结束时界面都是"可用且诚实"的状态，不会出现半成品假控件。

---

## 5. 明确不做（守原则，沿用 PRD §6）

- ❌ 不保留任何硬编码/编造指标（如假涨跌）。
- ❌ 不添加无后端支撑却假装可用的按钮（创建订单、假筛选、提前放出的重新下单）。
- ❌ 不另起「AI 全自动匹配大按钮」类无意义自动化。
- ❌ 不在订单中心新建物流模板/重量配置（设计稿 §2.6 已拍板复用共享数据）。
- ❌ 不渲染收件人 PII（仅跳 Shopify Admin，延续 PII 隔离）。
