# 订单中心 · 视觉与交互体验审计 + 改造规划 PRD

> 状态：**审计稿 / 规划阶段**，暂不开发。
> 目的：围绕「订单页面作为一个运营中枢，视觉与交互还缺什么」做体检，输出问题清单、缺失能力矩阵与优先级路线图。
> 约束：延续用户铁律与「不做 AI 感无意义东西」原则——所有条目要么真实可用、要么明确标注待后端、不允许编造装饰。

## 1. 审计范围与方法

  - 设计稿 `docs/ORDER_CENTER_DESIGN.md`（§2.3 字段矩阵 / §4 UI 样式 / §2.5 物流双轨）。

## 2. 问题审计（按严重度）

| # | 问题 | 位置 | 影响 | 建议 |

| P0-4 | **详情抽屉缺失（最大缺口）** | 设计稿 §2.3/§4.3 要求抽屉；现仅右栏小卡 page.tsx:187-209 | 点击行无全字段详情，字段矩阵（补款/应付/物流单号/双轨）无处展示 | 实现**详情抽屉**（右侧滑出或独立列），渲染 §2.3 全字段 + 物流双轨迷你进度条 |
| P0-5 | **行内「更多」按钮死互动** | order-table.tsx:182-188 ChevronDown 无行为 | 看起来可点实则无效 | 改为**真实行操作菜单**（查看 / 跳 Shopify / 按状态动作），或移除 |

| P0-7 | **加载/失败态薄弱且无感知** | loading 仅一行小字 page.tsx:244-258；fetch 失败静默回退 mock | 用户分不清真实/示例；大列表无骨架 | 加**骨架屏**；回退 mock 时顶部明确横幅「接口异常，已降级为示例数据」 |

## 4. 推荐改造方案（视觉 + 交互）

### 4.1 导航整合（解决 P0-1/P0-2）
- **移除状态卡的点击切换**：状态卡改为纯统计概览（图标+计数+真实子指标），当前状态用 ring 高亮，不再作为按钮。
- **Tab 药丸为唯一导航**：保持 8 状态 + 全部，计数徽标。
- **涨跌替换为真实指标**：用「今日新增 / 待处理 / 超时」三类真实派生数（从 `orders` 计算），删除 `DELTAS`。

### 4.2 头部操作区（解决 P0-3）
- 移除「创建订单」按钮（概念错误）。
- 保留「导出」→ 接真实 CSV 导出（与 Copilot 导出合并为同一 handler，避免两处实现）。
- 增加「刷新」按钮（P1-4）+ 数据源横幅（P0-7）。

### 4.3 详情抽屉（解决 P0-4/P0-5，最大价值）
- 点击行 → 右侧滑出 `OrderDetailDrawer`，渲染 §2.3 字段矩阵：
  - 常驻：店铺订单号 / Tangbuy 单号 / 创建时间 / 状态徽标 / 支付状态。
  - 按状态区块：待补款(原因+金额) / 待支付(应付+方式) / 备货中(预计发货) / 待发货·待送达(**五楼单号 + 物流双轨迷你进度条**) / 已送达(签收) / 已取消(原因+退款)。
  - 成本汇总：商品成本 / 物流成本 / 合计。
  - 操作：跳 Shopify / 按状态动作（后端就绪后启用）。
- 抽屉内嵌物流双轨组件（国内段 + 国际段双迷你进度条，异常 warning/danger 色）。
- 行的「更多」按钮并入抽屉入口（或移除）。

### 4.4 表格增强（P1-1~P1-6）
- 表头可排序（金额/时间/状态）。
- 行首 checkbox + 顶部批量操作条。
- 分页（每页 20/50）或虚拟滚动。
- 商品图真实加载 + 无图回退。
- 空状态三态：加载中（骨架）/ 真无订单 / 筛选无匹配（带清除）。

### 4.5 数据可用性诚实化（P0-6/P0-7/P0-8）
- 国家筛选、物流停滞筛选在后端字段到位前：**禁用 + tooltip「待数据接入」**，不呈现为假可用。
- 回退 mock 时顶部横幅告警，避免误判真实数据。
- **商品明细（标题/SKU/数量/图）**（P0-8）：真实订单头的 `lineItems` 为空，表格商品列、右栏预览、详情抽屉商品区**不得留白假象**——显示「待同步商品明细」占位并引导「查看订单详情」跳 Shopify 看完整商品；根治见 Phase 5 订单详情接口 + 抽屉展开时懒加载填充 `lineItems`（同时让按标题/SKU 搜索对真实单生效）。

## 5. 优先级路线图

| 阶段 | 条目 | 依赖 | 价值 |

## 6. 明确不做（守原则）

- ❌ 不保留任何硬编码/编造的指标数字（如假涨跌）。
- ❌ 不添加无后端支撑却假装可用的按钮（创建订单、假筛选）。
- ❌ 不另起「AI 全自动匹配大按钮」类无意义自动化（延续 SKU 对齐决策）。
- ❌ 不在订单中心新建物流模板/重量配置界面（设计稿 §2.6 已拍板复用共享数据）。
- ❌ 不渲染收件人 PII（仅跳 Shopify Admin，延续 PII 隔离决策）。

## 7. 验收标准（P0 完成定义）

1. 全站只有**一种**状态导航控件，8 状态全覆盖，状态卡为只读概览。
2. 页面**无任何**硬编码假指标；所有数字来自 `orders` 真实派生。
3. 无死按钮、无死「更多」；头部仅保留真实可用操作。
4. 点击任意行打开**详情抽屉**，可见 §2.3 全字段（mock 数据即可）。
5. 国家/停滞筛选在缺数据时**禁用并标注**，不假可用。
6. 回退 mock 时顶部有**明确告警横幅**；loading 有骨架屏。
7. 待下单(真实订单)商品列不再留白假象，显示**诚实占位**或真实明细；按标题/SKU 搜索对真实单在数据补齐后生效。
8. `npx tsc --noEmit` 0 错误（沿用项目验证方式）。
