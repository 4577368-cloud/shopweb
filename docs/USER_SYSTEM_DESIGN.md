# 用户账户体系设计文档

> 版本：v1.0 · 2026-07-25
> 决策：扩展 Java 后端（tangbuy-plugin）+ 自建 JWT（httpOnly cookie）+ 一用户多店铺

## 一、设计目标

1. **独立用户体系**：注册 / 登录 / 改密，密码 bcrypt 哈希入库
2. **先登录后绑店**：用户身份与 Shopify 授权解耦，一个用户可绑定多个 Shopify 店铺
3. **双账户体系**：
   - 余额账户（CNY）：充值 → 支付订单 / 购买增值服务
   - 积分账户：购买积分包 / 订阅发放 → 运营中心 API 消耗
4. **增值服务**：订阅套餐（含 X 积分）+ 积分包（单次购买），支付暂不接入只设计定价
5. **用户中心**：统一管理资料、店铺、账户、计费、配置、用量、通知

## 二、架构总览

```
浏览器 (Next.js 16)                Java 后端 (tangbuy-plugin)            Postgres / H2
┌────────────────────┐            ┌──────────────────────────────┐    ┌──────────────┐
│ /login /register   │  JWT cookie │ /api/plugin/auth/*           │───►│ users        │
│ /account/*         │◄───────────│ /api/plugin/user/*           │    │ user_shops   │
│ /bind-shop         │            │ /api/plugin/billing/*        │    │ user_accounts│
│ middleware 校验     │───────────►│ JwtAuthFilter + bcrypt       │    │ user_credits │
│ useUser hook       │            │                              │    │ subscriptions│
└─────────┬──────────┘            └──────────────────────────────┘    │ payment_orders│
          │                                  │                         └──────────────┘
          │ Shopify OAuth（登录后发起）        │ 复用 ShopifyAuthService
          └──────────────────────────────────┘
```

### 关键原则

| 原则 | 说明 |
|---|---|
| 用户身份 = JWT | httpOnly cookie，7 天有效期，refresh 策略待定 |
| 先登录后绑店 | Shopify OAuth 回调时带 userId，落 `user_shops` |
| 账户在 user 维度 | 余额、积分跨店铺共享，不按店铺隔离 |
| 双账本独立 | 余额账户（CNY）与积分账户互不转换 |
| 支付暂不接入 | 支付订单生成 status=pending，待支付网关接入后补回调 |

## 三、数据模型

所有表加到 `tangbuy-plugin/src/main/resources/schema.sql`，字段类型用 `BIGINT` 存金额（分为单位）、`INT` 存积分。

### 3.1 用户与鉴权

```sql
-- 用户主表
CREATE TABLE IF NOT EXISTS users (
  id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  email           VARCHAR(255) NOT NULL UNIQUE,
  password_hash   VARCHAR(255) NOT NULL,          -- bcrypt
  name            VARCHAR(128) NOT NULL,
  avatar_url      VARCHAR(512),
  locale          VARCHAR(8)   DEFAULT 'zh',      -- 语言偏好
  timezone        VARCHAR(64)  DEFAULT 'Asia/Shanghai',
  currency        VARCHAR(8)   DEFAULT 'CNY',     -- 展示货币偏好
  ai_response_language VARCHAR(8) DEFAULT 'zh',   -- AI 响应语言
  status          VARCHAR(32)  DEFAULT 'active',  -- active / suspended / deleted
  created_at      TIMESTAMP    DEFAULT CURRENT_TIMESTAMP,
  updated_at      TIMESTAMP    DEFAULT CURRENT_TIMESTAMP,
  last_login_at   TIMESTAMP
);

-- 用户-店铺绑定（一用户多店铺）
CREATE TABLE IF NOT EXISTS user_shops (
  id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id         BIGINT       NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  shop_name       VARCHAR(128) NOT NULL,          -- 对应现有业务表的 shop_name
  display_name    VARCHAR(128),
  is_primary      BOOLEAN      DEFAULT FALSE,
  bound_at        TIMESTAMP    DEFAULT CURRENT_TIMESTAMP,
  unbound_at      TIMESTAMP,
  UNIQUE(user_id, shop_name)
);

-- 刷新令牌（支持登出失效 + 多设备）
CREATE TABLE IF NOT EXISTS user_refresh_tokens (
  id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id         BIGINT       NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  token_hash      VARCHAR(255) NOT NULL UNIQUE,   -- refresh token 的哈希
  expires_at      TIMESTAMP    NOT NULL,
  created_at      TIMESTAMP    DEFAULT CURRENT_TIMESTAMP,
  user_agent      VARCHAR(512),
  ip              VARCHAR(64)
);
```

### 3.2 账户余额（CNY）

```sql
-- 用户余额账户（一对一）
CREATE TABLE IF NOT EXISTS user_accounts (
  id                BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id           BIGINT   NOT NULL UNIQUE REFERENCES users(id) ON DELETE CASCADE,

  created_at        TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at        TIMESTAMP DEFAULT CURRENT_TIMESTAMP

-- 余额变动流水
CREATE TABLE IF NOT EXISTS account_transactions (
  id                BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id           BIGINT   NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  type              VARCHAR(32) NOT NULL,         -- recharge / consume / refund / adjust
  amount_cny        BIGINT   NOT NULL,            -- 正数=入账，负数=出账
  balance_before    BIGINT   NOT NULL,
  balance_after     BIGINT   NOT NULL,
  ref_type          VARCHAR(32),                   -- order / subscription / credit_pack / recharge / manual
  ref_id            VARCHAR(64),
  remark            VARCHAR(255),
  created_at        TIMESTAMP DEFAULT CURRENT_TIMESTAMP

CREATE INDEX IF NOT EXISTS idx_acc_txn_user_created ON account_transactions(user_id, created_at DESC);
```


## 四、API 设计

所有新增接口在 Java 后端 `tangbuy-plugin`，前缀 `/api/plugin`（Next.js 通过 rewrite 透传）。

### 4.1 鉴权 API

| Method | Path | 说明 | 鉴权 |
|---|---|---|---|
| POST | `/api/plugin/auth/register` | 注册（email/password/name）→ 签发 JWT | 公开 |
| POST | `/api/plugin/auth/login` | 登录 → 签发 JWT httpOnly cookie | 公开 |
| POST | `/api/plugin/auth/logout` | 登出 → 清 cookie + 失效 refresh token | 需登录 |
| POST | `/api/plugin/auth/refresh` | 刷新 access token | 需 refresh cookie |
| GET | `/api/plugin/auth/me` | 当前用户 + 余额 + 积分 + 订阅概览 | 需登录 |
| POST | `/api/plugin/auth/change-password` | 修改密码（需当前密码验证） | 需登录 |
| POST | `/api/plugin/auth/forgot-password` | 忘记密码（生成 reset token，暂记日志） | 公开 |
| POST | `/api/plugin/auth/reset-password` | 重置密码（token 校验） | 公开 |

**JWT 结构**：
```json
{
  "sub": 123,           // user_id
  "email": "x@y.com",
  "iat": 1719...,
  "exp": 1719...        // 7 天
}
```

**Cookie 配置**：
```
Set-Cookie: tb_access=eyJ...; HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=604800
Set-Cookie: tb_refresh=eyJ...; HttpOnly; Secure; SameSite=Lax; Path=/api/plugin/auth/refresh; Max-Age=2592000
```

### 4.5 Shopify OAuth 改造

现有流程：`/api/plugin/shopify/auth/install?shop=xxx` → 回调落 `shopify_store_auth`

改造后：
1. 前端发起时带 `userId`：`/api/plugin/shopify/auth/install?shop=xxx&userId=123`
2. state 参数编码 userId：`state=UUID:userId`
3. 回调时除了落 `shopify_store_auth`，还写 `user_shops(user_id, shop_name)`
4. 若该 shop 已被其他用户绑定，返回错误「该店铺已绑定其他账户，请联系客服」

### 4.6 鉴权过滤器改造

新增 `JwtAuthFilter`（Java 后端）：
- 校验 `tb_access` cookie 中的 JWT
- 注入 `userId` 到 request attribute
- 放行：`/api/plugin/auth/{register,login,forgot-password,reset-password}`、`/api/plugin/health`、`/api/plugin/shopify/webhook/**`
- `ShopifyAuthController` 的 install/callback 路由特殊处理（OAuth 流程）

## 六、用户中心全功能盘点

基于项目现有模块（12 个页面、21 个 API、5 个 Agent、8 类配置、9 类统计），用户中心应包含以下 8 个板块：

### 6.1 概览 Dashboard（`/account`）

聚合展示跨模块健康度：

| 区块 | 内容 | 数据来源 |
|---|---|---|
| 账户卡 | 余额（CNY）+ 积分余额 + 当前订阅 | `billing/overview` |
| 店铺卡 | 已绑店铺数 + 主店名 + 授权状态 | `user/shops` |
| 今日用量 | 积分消耗数 + 订单数 + API 调用数 | `billing/credits/transactions` |
| 待办 | 订阅到期天数 + 积分预警 + 未读通知 | `notifications` + `subscriptions` |
| 各模块进度 | 选品匹配率 / SKU 对齐率 / 物流完成度 / 订单处理率 | 跨模块汇总 API |

### 6.2 个人资料（`/account/profile`）

| 字段 | 来源 | 说明 |
|---|---|---|
| 头像 | 新增 | 上传到 OSS |
| 姓名 | users.name | |
| 邮箱 | users.email | 不可改（或单独验证流程） |
| 语言偏好 | users.locale | en/fr/es/zh |
| 时区 | users.timezone | 补全现有缺失 |
| 展示货币 | users.currency | CNY/USD/EUR |
| AI 响应语言 | users.ai_response_language | Agent 输出语言 |

### 6.3 安全设置（`/account/security`）

| 功能 | 说明 |
|---|---|
| 修改密码 | 需输入当前密码验证 |
| 活跃会话 | 列出所有登录设备（IP / UA / 时间） |

## 八、鉴权流程

### 8.1 注册流程

```
用户填表（email/password/name）
  → POST /api/plugin/auth/register
  → Java 校验 email 唯一
  → bcrypt 哈希密码（cost=12）
  → INSERT users + user_accounts（balance=0）+ user_credits（balance=0）
  → 签发 JWT → Set-Cookie tb_access + tb_refresh
  → 返回用户信息
  → 前端跳转 /bind-shop
```

### 8.2 登录流程

```
用户填表（email/password）
  → POST /api/plugin/auth/login
  → Java 查 users by email
  → bcrypt.matches(password, password_hash)
  → 签发 JWT → Set-Cookie
  → 更新 last_login_at
  → 返回用户信息 + 余额 + 积分
  → 前端跳转 redirect 参数 或 /account
```

### 8.3 绑定店铺流程

```
用户点击「绑定店铺」
  → POST /api/plugin/user/shops/bind { shopDomain }
  → 后端校验该 shop 是否已被其他用户绑定
  → 302 → /api/plugin/shopify/auth/install?shop=xxx&userId=123
  → Shopify OAuth 同意页
  → 回调 /api/plugin/shopify/auth/callback?code=xxx&state=UUID:123
  → Java 校验 HMAC + 换 token + 落 shopify_store_auth
  → INSERT user_shops(user_id=123, shop_name=xxx)
  → 注册 webhook + 异步商品同步
  → 302 → /authorize?shop=xxx&bound=true
```

### 8.4 middleware 校验

```typescript
// 伪代码
export function middleware(request) {
  const { pathname } = request.nextUrl;

  // i18n locale（保留现有）
  // ...

  // 受保护页面
  if (isProtectedPage(pathname)) {
    const accessToken = request.cookies.get('tb_access')?.value;
    if (!accessToken) {
      return redirectToLogin(pathname);
    }
    try {
      const payload = verifyJwt(accessToken);
      // 注入 userId 到 request headers
      request.headers.set('x-user-id', String(payload.sub));
    } catch {
      return redirectToLogin(pathname);
    }
  }

  // 已登录访问 auth 页
  if (isAuthPage(pathname) && hasValidToken(request)) {
    return NextResponse.redirect(new URL('/account', request.url));
  }
}
```

## 九、迁移策略

### 9.1 现有 localStorage 数据迁移

| 现有键 | 迁移策略 |
|---|---|
| `tangbuy.shopDomain` | 登录后绑定到 user_shops，删除 localStorage |
| `tangbuy.authSessionOk` / `authLocalOk` | 由 JWT cookie 替代，删除 |
| `tangbuy.ops.accountBalance` | 由 `billing/credits/balance` 替代，删除 |
| `tangbuy.order.balance.cny.v1` | 由 `billing/overview` 替代，删除 |
| `tangbuy.order.internal.v1` | 保留（订单内部态 mock，待后端就绪） |
| `tangbuy:hub-mode` | 保留（dev 开关） |

### 9.2 店铺数据归属迁移

现有业务表隔离键是 `shop_name`，不侵入。通过 `user_shops` 表建立 `user_id ↔ shop_name` 映射：
- 查询用户数据时：先 `SELECT shop_name FROM user_shops WHERE user_id=?` → 再按 shop_name 查业务表
- 不需要给现有业务表加 `owner_user_id` 列

### 9.3 授权店铺列表过滤

现有 `/api/plugin/shopify/auth/shops` 返回所有 ACTIVE 店铺。改造为：
- 带上当前 userId
- `SELECT s.* FROM shopify_store_auth s JOIN user_shops u ON s.shop_name = u.shop_name WHERE u.user_id = ? AND u.unbound_at IS NULL`

## 十一、技术约束与风险

| 约束 | 应对 |
|---|---|
| Java 后端 README 写「不承接账号体系」 | 更新 README，扩展后端职责边界 |
| Next.js 16 breaking changes | 鉴权库自建 JWT（不依赖 next-auth），避免兼容性问题 |
| 现有业务表隔离键是 shop_name | 通过 user_shops 映射表解决，不侵入业务表 |
| pipispy API key 是账户级共享 | Tangbuy 统一持有 key，按用户记账（积分账本 + 计费拦截） |
| 支付暂不接入 | 支付订单 status=pending，待支付网关接入后补回调 |
| 密码安全 | bcrypt cost=12，禁止明文日志 |
| JWT 安全 | httpOnly + Secure + SameSite=Lax，refresh token 哈希入库可吊销 |
