## 0. 全局框架（所有屏共用）

```
┌────────────┬────────────────────────────────────────────┬──────────────┐
│  左栏       │  中栏（主工作区）                            │  右栏 AI      │
│  HubSidebar│  ┌──────────────────────────────────────┐   │  AssistantRail│
│  (中枢导航) │  │ Top Tab： 发现 │ 竞店 │ 素材          │   │  Copilot      │
│            │  ├──────────────────────────────────────┤   │              │
│ 运营中枢   │  │ 上下文条（本次预估 / 上次 actual）    │   │ 输入框+指令   │
│  ·订单中心 │  ├──────────────────────────────────────┤   │ chips         │
│  ·运营中心*│  │ 主内容（随 Top Tab 切换）            │   │ 消息流        │
│  ·履约中心 │  │                                      │   │              │
│            │  └──────────────────────────────────────┘   │              │
│ ─────────  │                                             │              │
│ Watchlist  │  + 统一详情抽屉（从右侧或中部滑出）         │              │
│ 本店用量   │                                             │              │
└────────────┴────────────────────────────────────────────┴──────────────┘
```

- 三栏宽度沿用 `WorkspaceLayout`：左 `--wb-sidebar-w`、右 `--wb-rail-w`，中栏自适应。
- 左栏 `HubSidebar` 是**中枢导航**（与订单中心同壳）：在「运营中枢」组里，运营中心为 active。
- 右栏 `AssistantRail` 是**营销 Copilot**，全屏常驻（见 §6）。
- 详情类内容统一走**抽屉**（Drawer），不另开整页。
- **Logo / 店铺选择器 / 用户菜单 / 语言切换**：由复用 `HubSidebar`（`AppLogo` / `ShopSwitcher` / `SidebarUserMenu` / `LanguageSwitcher`）提供，本 Brief 不另画 —— 设计师首轮图左上角的 logo 与店铺选择器即对应此复用件，无需重做。

## 1. 左栏（HubSidebar + Watchlist + 用量）

```
左栏（从上到下）
┌─────────────────────────┐
│ 中枢导航（订单/运营/履约）│  ← 复用，运营中心 active
├─────────────────────────┤
│ Watchlist                │
│  ├ TTS 店铺  (n)  ▸      │  ← 分组折叠，点击跳发现·TTS
│  ├ 竞店      (n)  ▸      │  ← 点击跳竞店视图并预填
│  └ 广告商品  (n)  ▸      │  ← 点击跳发现·广告商品
│  [＋ 添加]  [↻ 同步]     │  ← 小 icon 按钮
├─────────────────────────┤
│ 本店用量（本月）          │
│  实际消耗  ▮▮▮▮▮▯  123 点 │  ← MetricSummaryCards
│  [用量明细]              │  ← 打开用量明细抽屉
└─────────────────────────┘
```

要点：
- **不设左栏二级菜单**：模块 Tab（发现/竞店/素材）只在中栏 Top Tab 出现。
- Watchlist 三组可折叠；每组项点击 = 在中栏打开对应视图并带入上下文（如预填店铺 ID）。
- 「本店用量」= 本月 `SUM(actual_consumed)`；点「用量明细」开抽屉（见 §5.4）。

## 3. 视图一 · 发现（Discovery）

### 3.1 结构
```
发现
┌──────────────────────────────────────────────────────────┐
│ 分段： [ TTS 店铺 | 广告商品* ]                             │
│ 广告商品内分段： [ 排行* | 搜索 ]                           │
├──────────────────────────────────────────────────────────┤
│ 筛选栏：                                                    │
│  周期 [日|周|月]  排序[增长数▾|增长率|视频数]               │
│  地区[▾]  类目[▾]  店型[▾]  平台[TikTok|Facebook|全]        │
│  [搜索框…] [搜索按钮]                                       │
├──────────────────────────────────────────────────────────┤
│ 结果表（分页）：                                            │
│  # │ 封面 │ 标题 │ 价格(USD) │ 增长% │ 视频数 │ 平台 │ ★  │
│  1 │ ▢   │ …   │ $12.3     │ +34%  │ 5     │ TT   │ ☆  │
│  2 │ ▢   │ …   │ $8.9      │ +12%  │ 2     │ FB   │ ★  │
│  …                                                         │
│  [下一页]                                                  │
└──────────────────────────────────────────────────────────┘
```

### 3.2 元素标注
- **周期切换**：日/周/月（对应 pipispy `type` 1/2/3）。
- **排序控件**：增长数 `count_growth` / 增长率 `growth_rate` / 视频数 `video_count`，下拉 + 升/降。
- **筛选**：地区、类目、店型、平台（枚举来自 §2.8，UI 用下拉，不手敲码表）。
- **结果表列**：排名、封面缩略、标题、价格(USD)、增长%、视频数、平台徽标（TikTok 品红 / Facebook 蓝 / Meta Library 深蓝 小圆点）、收藏星标。
- **行操作**（hover 或「⋯」菜单）：看竞店（`competition(product_id)` 跳竞店视图）、看详情（开抽屉）、学素材（切素材 Tab）。
- **计费提示**：翻页/搜索前若未缓存，上下文条显示「预估 ~20 点」；确认后（见 §6 护栏）才发请求。

### 3.3 状态
- 空态：未选筛选/未搜索 → 中栏说明「选择周期与排序，查看热门广告商品」。
- 加载：表区骨架屏。
- 错误：红框 + 「重试」（代理未接通 / key 失效 / 配额不足）。
- 缓存命中：Toast「未消耗（缓存）」。

### 4.2 元素标注
- **搜索入口**：店铺 ID（13 位串）/ 店铺 URL → 回车或「查询」；或从 Watchlist 选。
- **平台分段**：全部 / TikTok / Facebook / Meta Library，切换展示对应平台细分字段。
- **竞店卡片**：投放状态徽标（活跃=绿 / 下架=灰 / 停投=红，映射语义 token）、店名+头像、平台徽标、全平台广告数、总播放/展示、CPM 区间(USD)、预估订单区间、投放天数、月访问量、品类标签 `ai_category[]`、最新素材缩略（`good_source[]` ≤3）。
- **卡片操作**：「看详情」开竞店详情抽屉（见 §5.3）；「☆收藏」加入 Watchlist。
- **监控态**：收藏店铺后，状态变化（新开投 / 播放激增）高亮提示（角标或行首闪烁点）。

### 4.3 状态
- 空态：未查询 → 厚说明「输入 pipispy 店铺 ID 查看竞店在投广告与增长趋势」，不伪造数据。
- 加载 / 错误 / 缓存命中：同 §3.3。

## 6. 右栏 · 营销 Copilot（AssistantRail）

```
┌────────────────── 营销 Copilot ──────────────────┐
│ 消息流：                                          │
│  你：分析一下这个竞店的卖点                       │
│  Copilot：该店主投 TikTok，TOP 素材卖点…          │
│  你：改写文案                                     │
│  Copilot：⚠️ 文案数据源不可用，已基于标题生成…   │
├──────────────────────────────────────────────────┤
│ 建议指令 chips：                                  │
│  [分析卖点/钩子] [改写文案(降级)] [对比竞店]      │
├──────────────────────────────────────────────────┤
│ [ 输入框…                        ] [发送]         │
└──────────────────────────────────────────────────┘
```

- 指令 chips：分析卖点/钩子、改写文案（降级）、对比竞店。
- 任何会触发出站调用的指令 → **先弹积分护栏**（见下）显示「预估消耗 N 点」，确认后才执行。
- 「改写文案」因 pipispy 无创意文案正文，降级为基于商品 `title` / 卖点有限生成，UI 标注「文案不可用」。

### 6.1 积分护栏 Modal（全局，任意出站前）
```
┌──────── 确认消耗 ────────────────┐
│ 本次操作预估消耗 N 点。            │
│ 当前剩余：M 点                     │
│ [取消]              [确认并继续]   │
└──────────────────────────────────┘
```
- 仅确认后发出真实请求；失败 → 红框 + 剩余点数。
- 目的：保护 pipispy 预算不被刷爆（我方付费，向商家收费后续独立设计）。

## 7. 视觉规范引用（设计师必读）

- **壳/布局**：复用 `WorkbenchShell` + `HubSidebar` + `AssistantRail` + `WorkspaceLayout`，三栏宽度沿用现有变量。
- **组件（禁止手写替代品）**：
  - 按钮 `Button`（variant: primary / secondary / ghost / danger / link）
  - Top Tab `SegmentedTabs`（variant="chip"）
  - 指标卡 `MetricSummaryCards`、面板 `WorkbenchPanel`、表格 `Table`
- **语义 Token（禁止硬编码颜色）**：
  - 正文 `text-ink` / `text-ink-muted` / `text-ink-subtle`
  - 边框 `border-hairline`；表面 `bg-surface` + `shadow-card`
  - 成功/live `bg-success-soft text-success`；降级/占位 `bg-muted text-ink-muted`
  - 链接 `text-link`；表格选中行 `bg-surface-selected ring-brand`
- **品牌色约束**：Sourcing Mint（`--brand`）仅用于货源/选品/正向 CTA；竞店状态、中性统计**不得**误用 mint 当成功绿，用 success / muted / danger token。
- **平台徽标色**：TikTok 品红、Facebook 蓝、Meta Library 深蓝（小圆点/角标，不覆盖整卡背景）。
- **扣费用量**：预估/actual 用 warning / neutral chip 或上下文条；错误才用红；缓存命中用 success-soft 轻提示。
- **图标**：用 `@/lib/ui/icons`（Polaris 系），如 Search / Store / Sparkles / Target。
- **i18n**：文案走 `ops.*` 四语，不进组件硬编码（设计师用占位文案即可）。

## 8. 设计待定项 · v1 默认取值（已决，无需再问）

v1 前端交互（mock 驱动可点击原型）按以下默认值落定：

1. **默认落地 Tab**：**发现**（设计师首轮图默认即发现，且最贴近"先浏览再深入"的黄金链路）。
2. **左栏 Watchlist**：**保留**（三组 + 用量卡，见 §1）。
3. **竞店卡片信息密度**：**全字段卡**（§4.1，状态徽标 + 广告数/播放/CPM/最新素材缩略一屏展示）。
4. **Copilot 形态**：v1 **静态建议指令 + 文案降级**（不接真实 LLM，零成本、可预测），沿用订单中心确定性 command 范式；"改写文案"降级为基于商品 `title` 有限生成或标注「文案不可用」。
5. **积分护栏强度**：v1 仅**确认弹层**（不硬拦截、不加月预算上限进度）；每次出站前弹「预估 N 点 → 确认」，失败红框 + 剩余点数。
6. **两处已知限制呈现**（必画）：
   - 视频取流未通 → 素材/详情封面仅**缩略图灰显** + 「取流未通」角标，无播放按钮；
   - 创意文案无数据源 → 详情抽屉内**「文案不可用」降级提示条**（§5.1）。
